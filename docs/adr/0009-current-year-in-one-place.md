# 今の年はプラグインの設定の1か所で管理者が決め、管理画面の年はすべてそこから決める

管理画面で扱う「今の年」は、自作プラグイン admin-guard の設定（`currentYear`）の1か所に置く。変えられるのは管理者だけで、変える方法は次の2つ。

- 管理画面のプラグイン → admin-guard → 設定
- MCP の道具 `admin-guard__current_year`

管理画面の次のものは、すべて今の年から決まる。

| | 今の年からどう決まるか | 実現の仕方 |
|---|---|---|
| 新しく作る中身の年 | 画面の年の欄に、今の年が初めから入る | `middleware.ts` で、manifest の年の項目の既定値を今の年に置き換える |
| 新しく作る中身の年（API・MCP） | 年を入れずに作ると、今の年が入る | 保存のフック（`content:beforeSave`） |
| 一覧の画面 | 全員に、今の年の中身だけを出す | `middleware.ts` で、一覧の要求に年の絞り込みを足す |
| カテゴリ・ステージの候補 | 今の年のものだけを出す | 同上 |
| 実行委員が扱える中身 | 今の年の中身だけ | ADR 0008 |

前の年の中身は、プラグインのページ「前の年の中身」に、コレクションごとに並べる。各行から編集の画面を開ける。カテゴリとステージは、サイドバーの「設定」のフォルダ（コレクションの `group`）にまとめる。

公開サイトに載せる年（`web/src/lib/cms.ts` の `YEAR`）は、今の年とは別のものとし、サイトごとに固定する。管理画面の今の年を次の年に変えて入力を始めても、公開中のサイトの中身は変わらない。

## Considered Options

- 年の既定値を各コレクションのスキーマに持たせ、今の年を変えるたびに直す: 今の年を変える道（設定の画面・MCP・API）ごとに、7つのコレクションの既定値を直すことになり、忘れると実行委員が新しく作るたびに断られるので採らなかった。
- 年の項目の必須を外し、保存のフックだけで今の年を入れる: EmDash 1.3.0 は必須の変更に中身の移行を求め（`FIELD_UPDATE_REQUIRES_MIGRATION`）、必須のままだと画面の年の欄が空では保存できないので採らなかった。
- 公開サイトが CMS の今の年を読む: 次の年の入力を始めた時点で、公開中のサイトが次の年の中身に替わる。プラグインの設定を読むには管理者の権限の token も要るので採らなかった。
- 一覧には今の年だけを出し、前の年の中身は MCP と API からだけ読む: 実行委員が画面で前の年を参考にできなくなるので採らなかった。
- 一覧は年を混ぜたまま出す: 年が増えるほど、今の年の中身が探しにくくなるので採らなかった。

## Consequences

- 画面の年の既定値は、manifest の形（`data.collections.<コレクション>.fields.year.defaultValue`）に頼る。EmDash を上げたときは、`docs/notes/admin-guard-checks.md` を流す。
- 管理者も、一覧の画面では前の年の中身を見られない。「前の年の中身」のページかゴミ箱から開く。
- 「前の年の中身」のページは、コレクションごとに新しい順の 100 件までを出す。
- MCP の道具を使うには、管理者がプラグインの MCP の道具を有効にし、token に `mcp:tools` の権限を付ける。
- 年が変わるときは、管理者が今の年を変え、その年のカテゴリとステージを作る。公開サイトの年は、次の年のサイトを作るときに変える。
