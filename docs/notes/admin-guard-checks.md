# 開催年と役割の決まり（ADR 0008・0009）の確かめ方

`cms/src/plugins/admin-guard.ts` と `cms/src/middleware.ts` が、管理画面の操作を決まりどおりに通す・断るかを、画面から確かめる。EmDash を上げたときと、この2つを直したときに流す。

## 用意

1. 手元の開発サーバーを起動し、dev-bypass で管理者として入る（HANDOVER の「手元で動かす」）。
2. 管理者で、前の年（開催年 − 1）の出展者とカテゴリを1件ずつ作って公開する。
3. 実行委員として試すときは、手元の D1（`cms/.wrangler/state/v3/d1/` の、使っている DB）の `users` の `role` を 40 にし、開発サーバーを起動し直す。役割は起動し直すまで前の値が残る。終わったら 50 に戻して起動し直す。dev-bypass で入り直すのは、役割を変える前に済ませる。
4. プラグインのコードを直したら、開発サーバーを起動し直す。ファイルの保存だけでは、フックが新しくならない。

## 実行委員（Editor、40）

## 管理者（Admin、50）

| | 操作 | 期待すること |
|---|---|---|
| A1 | カテゴリを新しく作って保存 | 保存できる |
| A2 | A1 のカテゴリをゴミ箱へ | ゴミ箱に移る |
| A3 | 前の年の出展者のひとことを直して保存 | 保存できる |
| A4 | 前の年の出展者をゴミ箱へ | ゴミ箱に移る |
| A5 | 前の年の出展者を複製 | 複製できる。年は前の年のまま写る |
| A6 | A5 の複製の年を開催年に直して保存 | 保存できる |

## 結果

- 2026-11-01（EmDash 1.3.0、手元）: E1〜E19、A1〜A11 のすべてが期待どおりであった。agent-browser で画面を操作し、出た文と、API で読んだ状態で確かめた。
  - 最初の試しで、複製が保存のフックを通らず、前の年の年のまま実行委員の複製ができた。実行委員の複製を `middleware.ts` で断るように直した（ADR 0008）。
  - 過去の開催のデータの削除は、はじめ `content:beforeDelete` で全員に断っていたが、管理者は消せるように `middleware.ts` で実行委員だけを断る形に変えた。その過程で、実行委員がゴミ箱から過去の開催のデータを復元できることが分かり、復元も断るようにした（E17）。
  - 最後の直し（削除と復元を `middleware.ts` に移した）の後に流し直したのは、E14・E15・E17〜E19・A4・A10・A11。ほかの項目は、その前の版で流した。最後の直しでは、保存・公開・複製・候補の処理は変えていない。
- 2026-11-01（同じ日の2回目）: MCP と版の復元を `middleware.ts` で断るように直した後、E2・E6・E11・E13・E14・E16・E20〜E28・A12〜A14 を流し、すべて期待どおりであった。E2・E6・E11・E13・E14・E16・E20〜E22・E24〜E25・A12〜A14 は API で（token は管理者の画面で作り、試した後に消した）、E23・E26〜E28 は画面のログインで確かめた。
  - token の権限（scope）が足りないときも 403 になる。役割で断られたことを見るには、画面のログインで API を呼ぶ（E26〜E28）。
  - 試していないこと: 実行委員による過去の開催のデータの下書きの破棄（discard-draft）と、分類の付け替え。下書きの破棄では公開中の内容は変わらず、分類は公開サイトが読まない。
- 2026-11-01（3回目、ADR 0009）: E16・E16b・E16c・E29〜E32・A7・A8・A15・A16 と、E11（前の年の出展者を直すと断られる）・E9（開催年の出展者を直せる）を流し、すべて期待どおりであった。A8 は MCP の道具で開催年を 2027 にして確かめ、2026 に戻した。
  - 年の項目の必須は、EmDash が中身の移行を求めるので外せない（`FIELD_UPDATE_REQUIRES_MIGRATION`）。必須のまま、画面の既定値を manifest で開催年にしている。
- 2026-11-01（4回目、「イベント設定」と「開催年」のページ）: A8（ページから 2027 にして新しく作る画面の年が 2027 になることを確かめ、2026 に戻した）・A16・A17・E33 を流し、すべて期待どおりであった。
